# Data directory

This folder holds the Customer Support on Twitter dataset and all derived
artifacts. **No raw CSV is committed to git** (see `.gitignore`).

```
data/
├── raw/        # source data only (gitignored)
└── processed/  # generated by scripts/prepare_data.py (gitignored)
```

## 1. Getting `twcs.csv`

Source: Kaggle — [thoughtvector/customer-support-on-twitter](https://www.kaggle.com/datasets/thoughtvector/customer-support-on-twitter)

Option A — Kaggle CLI (recommended, no account needed for public datasets):

```bash
kaggle datasets download -d thoughtvector/customer-support-on-twitter -p data/raw --unzip
```

Option B — manual download:
1. Visit the Kaggle dataset page above.
2. Click **Download** and unzip `archive.zip`.
3. Place `twcs.csv` in `data/raw/`.

The file is ~280 MB uncompressed (~2.8 million tweets). Expected columns:

| column | meaning |
|---|---|
| `tweet_id` | unique tweet id (18–19 digit snowflake id — must be parsed as **string**) |
| `author_id` | tweet author. For *outbound (support)* tweets this is the account screen name (e.g. `AppleSupport`); for *inbound (customer)* tweets it is a numeric id |
| `inbound` | `TRUE` if the tweet was sent *to* a brand, `FALSE` if sent *by* the brand |
| `created_at` | Twitter timestamp, e.g. `Tue Oct 31 21:00:00 +0000 2017` |
| `text` | tweet text |
| `response_tweet_id` | comma-separated ids of tweets that reply to this tweet |
| `in_response_to_tweet_id` | id of the tweet this tweet replies to (empty for conversation roots) |

## 2. Configuring the AppleSupport author id

The dataset has **no brand column**. Which account counts as "Apple Support"
is a configuration decision, not a hard-coded guess. In this dataset the
`author_id` of outbound tweets holds the account's screen name, so:

```bash
# lists the most frequent outbound author_ids — find Apple's support account there
python scripts/find_author_ids.py
```

Then set it in `.env` (copy `.env.example` → `.env`):

```
APPLE_SUPPORT_AUTHOR_ID=AppleSupport
```

## 3. Processed outputs

`scripts/prepare_data.py` writes into `data/processed/`:

| file | contents |
|---|---|
| `applesupport_tweets.csv` | every tweet belonging to a conversation AppleSupport took part in, with `conversation_id` + `turn` |
| `conversations.csv` | one row per AppleSupport conversation (size, timespan, tweet ids) |
| `conversation_pairs.csv` | customer message ↔ historical AppleSupport reply pairs (retrieval evidence for Phase 4) |
| `pipeline_run.json` | run metadata, cleaning report, validation results (reproducibility) |
| `eda_summary.json` | EDA statistics (consumed by the EDA notebook and the web dashboard) |
| `charts/` | EDA figures (PNG) |

## ⚠️ Historical-data disclaimer

The dataset contains **historical** customer-support interactions. Retrieved
AppleSupport responses are used strictly as *evidence* for retrieval,
grounding and evaluation — they are **not** a representation of current
Apple policy, pricing, or support practice.
